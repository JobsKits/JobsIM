## 五、<span id="send-admission-regression">原始发送准入与冻结</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

此前完整30项、4项定向与1项结果路径验证是前一基线，不将它们当作发送准入增量后的全量回归。本轮只执行针对新合同的测试，旧外置报告及SHA不改。

- Conversation原样保存本人`membershipGeneration`与`sendAdmission`；后者只按字符串使用，不自制、不从其他成员／账号取得，也不解析其内部版本。
- 创建消息意图时持久冻结原`sendAdmission`、`restoreEpoch`及`clientMsgId`；文件选定后在上传前取原准入，上传期间的新资格不会覆盖它。后续刷新缓存可以更新会话DTO，不能改旧Outbox。
- 升级真实旧SQLite结构时冻结缺快照记录，并保留Outbox原始BLOB逐字不变；自动pending只取queued。永久冻结的同ID不能靠重复enqueue或填新token复活；已提交权威结果仍可原子收口。
- 正式发送先重新确认`features.send_admission=true`；本轮后续已将冻结记录的显式“核对原结果”改为只读`message-results`，不再调用发送接口。服务器409 `SEND_ADMISSION_CHANGED`冻结，既有事实优先按原摘要和当前read ACL核验；无事实只读404不创建消息。
- UI把冻结显示为“发送已暂停／请核对原结果”，不会显示已接受；只提供原结果核对，不自动创建新ID或用最新token替换。暂停附件不预加载，普通历史导出不混入冻结的未确认意图。

升级前隔离测试账号已在8443旧binary实际提交1条无新字段的消息，原body／已提交ID进入测试fixture，bearer仅Keychain；升级后用它证明旧摘要兼容，而不是新服务下伪造旧记录。本轮1/1真实旧格式准备、7/7存储／状态定向（含2项原Outbox回归）、3/3新服务真实HTTPS定向全部通过；共11次用例执行、9个新增方法含1项准备，未重跑原30／4。新消息断言包括群未观察退重入、direct删除与拉黑新接受两轮，以及无新发送许可时已提交事实仍按read ACL回放。旧无字段已提交消息来自升版前真实服务，升版后原body对账成功；缺字段无既成ID返回SEND_ADMISSION_CHANGED且服务端历史零新增。
