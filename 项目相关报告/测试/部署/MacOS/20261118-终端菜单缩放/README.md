## <span id="jobs-toc-heading-1" data-jobs-toc="v2">一、显示机制与修正范围 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

用户截图显示拖动Terminal右下角调整尺寸后，网页菜单留下多层旧边框与选项。两份MacOS自包含脚本此前使用`--height=40%`，fzf在终端主缓冲内以相对游标和换行绘制；真实PTY对照确认该模式没有进入备用屏，连续尺寸变化仍在主缓冲重绘。当前前台选择器与后台网页菜单改为`--no-height`，使用独占备用屏，缩放后重绘，退出时归还原屏。未改第三方fzf、终端全局配置或已运行的部署实例。

后台选择器原先把Ctrl+C与Esc都归为普通130取消，和“Ctrl+C停止本轮服务”的提示不符。当前Ctrl+C绑定`print(__jobsim_interrupt)+accept`，控制器精确比对结果首行后返回130，沿已有错误陷阱与收尾流程处理本轮资源；Esc保持收起，普通回车仍只打开所选地址。`print+abort`在当前fzf不会写出标记，失败原件保留，不作为有效实现。只读工具门禁额外验证全屏及按键动作解析，未升级用户fzf。

## <span id="jobs-toc-heading-2" data-jobs-toc="v2">二、最终证据与限制 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

最终固定输入与原始TTY字节见[14组摘要](./1794972234359026000/summary.json)。测试入口为[菜单缩放.py](../../../../../测试/部署/MacOS/菜单缩放.py/README.md)，仅使用现有fzf `0.75.0 (Homebrew)`、Python标准库与zsh。

| 检查 | 实际结果 |
| --- | --- |
| 部署／反部署两份实现 | 各7组，共14组通过；源SHA独立记录，不和历史部署集成数量相加 |
| 尺寸变化 | 每组5次连续放大／缩小，含15×55窄窗口；真实TIOCSWINSZ与SIGWINCH均产生重绘 |
| 备用屏 | 新模式进入／退出成对，退出在清理输出前归还屏幕；旧高度对照没有备用屏协议 |
| 选择与取消 | 真实上下键、回车和Esc；普通选择保留临时假服务，Esc后回车可重新打开菜单 |
| 控制器中断 | 真实PTY输入`\x03`，有匹配及无匹配搜索均由生产monitor返回130并调用原错误陷阱，测试清理只处理本轮假服务 |
| 语法与副本 | 两份zsh解析及Python编译通过；除默认动作外，两份自包含实现逐字一致 |
| 工具能力 | [两源只读门禁](./1794972234359026000/只读能力门禁.json)均复用现有fzf，拒绝无法解析所需动作的假候选 |
| 目标界面 | CUA连接30秒超时，未执行Terminal图形界面拖拽目视验收；PTY协议通过不冒充该验收 |

中间失败与夹具修正原件保留在相邻时间编号目录。早期夹具清理未隔离命令替换子Shell、以及`CLEANING=1`屏蔽生产错误陷阱的失败均不计通过；最终以摘要固定源码及14组原始日志为准。测试未启动PG、NATS、真实浏览器或隧道，未改数据库、原实例身份、CA、密钥或用户数据，不代替完整部署／反部署集成。

## <span id="jobs-toc-heading-3" data-jobs-toc="v2">三、当前运行会话 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

旧控制器已把函数载入内存，不会因Esc收起再回车重新读取磁盘源码。修正从下次正常启动生效；本任务没有停止或重启用户现有服务。旧画面可先Esc收起，再用Terminal的⌘K清屏，回车重开；这仅暂时整理显示，旧参数和旧Ctrl+C行为仍在。暂停菜单不是Shell，输入`clear`不会执行命令。已有正常终端记录由备用屏返回继续保留，不清空全局滚屏或更改Profile。
