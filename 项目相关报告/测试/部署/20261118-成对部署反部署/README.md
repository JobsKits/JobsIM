## <span id="jobs-toc-heading-1" data-jobs-toc="v2">一、结论与责任边界 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

JobsIM 按李林哲项目组织六系统原生部署：`MacOS`、`Windows`、`Ubuntu`、`Debian`、`RockyLinux`、`AlibabaCloudLinux` 各有 `Deployment`／`Undeployment` 和成对快捷入口；公共组件与引导锁独立归类。原“停止备份”不再作为反部署入口，停止与备份仍可作为维护子动作。实际入口见[部署总览](../../../../部署/README.md)。

原生 Go 网关／业务角色、业务与独立 journal 双 PostgreSQL 物理集群及 NATS JetStream 直接运行；Node 只构建 Web 静态资源。客户端继续使用各平台原生语言，Web 同时覆盖桌面与手机 H5。低总体投入是设计目标，不能凭“原生”名称承诺更低内存或用一次启动代替持续负载测量。

**当前证据不能封版 T-44～46／ARCH-33。** Mac 有受控原生实例证据；Linux 四发行版与 Windows 的主机检查、隔离夹具不等于目标系统执行。非后端人员独立操作、真实公网／手机扫码、六系统完整恢复与生产托管／资源包络尚未验收；原 243 项保持原状态。

## <span id="jobs-toc-heading-2" data-jobs-toc="v2">二、参考、合同、实现与证据 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

参考工程为[啄木鸟维修平台现行部署](../../../../../啄木鸟维修平台/部署/README.md)，只读核对，未修改其源码。现行要求直接写入[需求总纲 2.11](../../../../需求/IM需求明细表.md/IM需求明细表.md#guided-installation)、[部署架构](../../../../需求/IM后端架构表.md/IM后端架构表.md#guided-deployment)、[前端架构](../../../../需求/IM前端架构表.md/IM前端架构表.md#mobile-web-h5)及[验收台账](../../../../需求/IM功能验收表.md/IM功能验收表.md)，不另立“升级后需求”版本。

| 对照点 | JobsIM 当前实现 | 实际证据与待验 |
| --- | --- | --- |
| 六系统成对入口 | 每系统双击部署／反部署，唯一实现位于Deployment／Undeployment的同名脚本包；Linux四发行版分别自包含，Windows使用原生PowerShell | 各平台摘要记录语法、参数、路径与源码SHA；Mac实际PTY／fzf，其他系统真实桌面双击待验 |
| 低配置与工具归属 | 从自身路径解析工程；健康工具复用，官方目标／能力与摘要复核；环境、缓存、业务数据及备份分别归属，不升级系统全局环境 | 公共版本工具与路径夹具；Windows缺少健康PG18工具时仍有明确先决条件，不能称干净机器零准备 |
| 本地与服务器模式 | 本地默认仅回环，穿透另选另确认；服务器模式使用实际URL／SAN／证书；本地就绪与公网就绪分开报告 | Mac实际受控服务器与本地模式分列；公网链路仍待实测。未实现管理页不生成假/admin入口 |
| 失败与会话生命周期 | 确认／模式取消不接管旧实例；本人PID与资源身份复核、锁串行、退出精确回收；Quick失败／晚退撤回旧URL及二维码，恢复回环Origin和本地健康 | 当前矩阵以夹具验证故障分支，真实关窗／系统原生进程回收和公网结果按平台另验 |
| 真正反部署 | 先选保留或清空，清空默认备份后清理；范围预览与危险动作独立确认，--yes不跳过清理确认 | Mac实际反部署；Linux／Windows隔离归属、改动／未知文件、链接及归档失败反例 |
| 可证明归属的清理 | created／reused原点、部署身份、设备／inode或平台等价身份与当前快照逐项核对；未知／后改对象保留，不递归抹除目录 | 当前安全矩阵分别列出拒绝结果；旧无原点实例不追认清理资格，清理不是整机回到原状 |
| 备份完整性与保护 | broker停止并核验清单，维护逻辑备份核验八库；冷备及逻辑备份分别说明。任何失败须阻止加密成功宣告及删除 | Mac真实八库／broker加密解密；Linux冷备逐文件及逻辑八库夹具、Windows归档夹具。未执行六系统全量恢复 |
| 独立恢复材料 | journal、匹配的Application/instance.json、Secrets、TLS及原备份／恢复密钥默认保留；受保护对象留下时报告部分完成 | Mac真实清理保护；host故障和保护夹具分列。不会将业务清理描述为销毁独立journal或全部秘密 |
| 扫码与Web交付 | 本地离线生成URL一致二维码，不携带凭据；网关同源提供桌面／H5静态资源，本地演示明确标识 | PNG真实解码及Mac实际响应字节核对；[H5报告](../../前端/Web/20261118-H5适配/README.md)单列模拟触控／视口和真机未验 |

## <span id="jobs-toc-heading-3" data-jobs-toc="v2">三、逐平台实际验证 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

Mac反部署实际子进程退出0表示完成所选可清范围，其持久phase和输出仍为受保护资料保留的partial；Linux／Windows保护保留时使用退出2。退出码按平台解释，均不表示整机恢复或journal／匹配密钥已销毁。

各层计数不相加为产品验收总数。原始失败、超时、中间结果及候选输入均保留；只引用摘要明确指向的最终输入。Mac后端集成后如仅有Web或菜单文案增量，以独立构建／真实返回字节与定向门禁记录范围，不追认原集成已跑新源。

## <span id="jobs-toc-heading-4" data-jobs-toc="v2">四、原回归遗漏与保留失败 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

[原回归报告](../../回归/20261118-全项目回归/README.md)执行了既有启停／备份测试，却没有验证需求中的同款交付和真正反部署，其“部署需求符合性”已明确为未通过。原日志和SHA保留；原测试通过不能补足当时漏掉的需求。需求是核对依据，已存在的测试不是完整验收清单。

本轮继续发现：Shell函数位于条件调用链时，set-e不能保证内部失败中止，早期broker归档失败可能继续进入CMS步骤。现按停止、dump／manifest、tar、加密及解密逐层显式传播错误，增设失败不得产生成功归档或删除的反例。旧候选即使曾记录成功，也不再作为完整备份证明；以各平台最终摘要的完整性证据为准。

H5原容器高度检查曾遗漏极短视口的sticky置顶遮挡；[H5原件](../../前端/Web/20261118-H5适配/README.md)同时保留修前与后续阅读反例。不能以截图数量、DOM高度或测试总数代替实际任务可完成。

## <span id="jobs-toc-heading-5" data-jobs-toc="v2">五、环境与复核入口 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

[独立部署测试](../../../../测试/部署/README.md)按平台组织，公共辅助测试亦在测试目录；测试代码不混入生产生命周期。运行数据、CA私钥、账户材料及唯一备份留在工程外，报告只存脱敏结果。默认用户实例、现有业务数据与既有恢复材料不作为清理夹具；只停止本轮有身份记录的进程，测试数据保留。

Mac收尾核对10个自有隔离夹具与46个唯一测试端口，未见自有控制器、Go、PG、NATS或隧道遗留；默认实例引用SHA前后相同。没有默认实例全量字节快照，故不把“未操作默认实例”扩大为全量字节未变证明。

每个平台的目标系统验收仍需按T-44～46记录操作者、必填项、人工介入、下载量、耗时、资源及失败恢复；完整双物理PG／broker／媒体恢复、强保护灾备和已选未来业务组件分别继续其合同，不以本轮原生入口减少需求。
