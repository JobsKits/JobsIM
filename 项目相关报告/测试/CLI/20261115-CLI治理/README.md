## 二、<span id="coverage">通过范围</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

- request／reopen 在各自 POST 前已提交原 ID／原载荷／摘要／代际；丢响应与数据库重开仍用原操作。已完成操作恢复不再次 POST，旧开放事实与当前本人 denied 门禁分开显示，恢复代际变化冻结旧治理意图。
- 删友／拉黑前只冻结该人的对应 direct；其他 direct／群保持原状态。冻结原因独立存储，原 payload 字节、sendAdmission、ID 和摘要不变。解黑不自动恢复好友或重开申请，reopen 后仍需新的申请／接受。
- 成员查询、加人、按原 generation 踢人、改名、转让、离群均经真实后端；旧踢人资格在重入后拒绝。本人原 leave generation 过时会在本地清理前拒绝，新的待发和历史保留。
- leave／remove-member 本人路径在网络删除前事务冻结该群、删除本机该群历史／游标并保留草稿；SQL 删除游标故障会回滚全部本地修改；未知 PATCH／DELETE 没有自动重放。
- 治理冻结的原消息 reconcile 只按当前身份、实例及恢复代际做 GET 历史分页。服务端撤权尚未收到时也不会 POST 首次创建旧消息；未找到仍未知，保持冻结。找到既成事实能确认原行，退群确认不回填已撤的本机历史。
- schema1→2 增量升级保留原 Outbox，新增独立冻结原因和治理原操作表。此前七组发送、恢复代际、原资格、游标／版本、旧JSONL与不可用正文保护仍通过。

真实 HTTPS 失败待发使用不存在的媒体对象触发真实服务端拒绝，再验证本地冻结和原载荷保留；丢响应及 SQL 失败由独立故障服务覆盖，不把这些模拟故障声称为生产宕机或断电演练。

## 三、<span id="limits">限制</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

治理只读对账最多 1000 页、每页 200，分页内不保存其他历史／游标。当前读取 ACL 拒绝、跨恢复代际或没有查到都保留未知，不能推断未提交。还没有按完整原 clientMsgId 载荷精确只查的独立接口，本轮不新增或伪造后端参数。未知服务端写结果须先查当前关系／成员，再由用户明确决定后续新意图；不会回滚服务端动作。

CLI 仍为终端客户端，没有图形主题／播放器／摄像头；完整快照、合格 ACK、清云、OS 强杀／断电和全部 I 门禁未验收。未提交、推送或签名发布。
