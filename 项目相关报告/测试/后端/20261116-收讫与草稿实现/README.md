## 🔥 <span id="前言">前言</span>

本轮在现有服务上新增部署批准的原生存储声明、完整原正文交付挑战、幂等正文收讫及原请求只读查单。默认部署没有批准项，所有存储继续仅传输资格；不凭客户端声明或网络收到授予云副本删除资格。与同轮[云草稿](../20261116-云草稿/README.md)分别记录证据，不合并测试数量。

## 一、<span id="implementation">代码与边界</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

- [策略解析](../../../../代码/后端/Go/sync_receipt_policy.go)按精确profile、原生构建SHA和存储验证报告SHA匹配部署批准项。外置策略有大小、字段和重复项校验；移除批准项立即使新进程中的旧声明失去资格。该策略是部署者批准记录，不是远程硬盘持久化证明，也不证明声明者实际运行了该二进制。
- [收讫实现](../../../../代码/后端/Go/sync_receipts.go)绑定本人、认证device、真实storeGeneration、恢复epoch、资格ID、原正文摘要、内容版本与当前权限代际；原nonce与完整body摘要持久去重。旧正文编辑、权限ABA、换设备、换库及恢复代际拒绝新确认；已提交事实只读返回原版本。
- 挑战返回原bodyEnvelope和SHA；原生端必须先校原字节，在本地FULL事务持久正文及原回执意图，再提交原挑战。服务端SQL成功不证明客户端已经执行这些动作。本轮尚未接入客户端receipt_outbox，也未验证原生持久配置。
- 附件描述不等于完整对象字节。当前拒绝引用转发正文、对象与累计回执，所有响应明确`objectComplete/targetRangeComplete/deletionEligible:false`；`after_receipt`继续关闭。冻结完整目标、对象回执、跨恢复删除事实和清理worker仍须继续实现。
