## 一、工程范围 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

标准浏览器客户端，使用 React、TypeScript 和 CSS；移动客户端另用各平台原生工程，不把网页封装为移动 App。产品范围见[现行需求](../../../需求/README.md)，入口关系见[代码地图](./代码地图/README.md)。

已落盘会话、联系人与申请、群聊、文本和附件、回复、编辑、撤回、表情回应、置顶、收藏、转发、搜索、设备、恢复码、个人名称、头像、举报、群治理、本机未读、十种语言、字号、白天／黑夜／跟随系统。界面只表示当前实现，完整第一阶段验收以[实现进度](../../../项目相关报告/实现进度/README.md)为准。

## 二、准备与运行 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

需要 Node.js 22.12 以上和 npm；包版本由 `package-lock.json` 锁定。

```sh
./Scripts/准备环境.command/准备环境.command --check
./Scripts/准备环境.command/准备环境.command
npm run dev
npm run build
```

准备脚本将依赖写入用户缓存，通过工程内的 `node_modules` 链接引用。缓存根目录可用 `JOBSIM_WEB_CACHE` 指定；不会升级全局 Node/npm。启动器从自身路径解析工程，直接执行 npm 时需在本目录运行。

开发地址默认为 `http://127.0.0.1:5178`。`/api` 代理默认请求 `https://127.0.0.1:8443`；可通过 `JOBSIM_API` 指定服务端，用 `JOBSIM_CA_FILE` 提供自建 CA。证书与主机名校验保持启用。

```sh
JOBSIM_API=https://localhost:9443 JOBSIM_CA_FILE=/your/private/ca.pem npm run dev
```

生产构建输出 `Dist/`；Go 网关的 `--web-dir` 指向该目录即可同源部署。见[部署入口](../../../部署/README.md)。

## 三、数据与故障处理 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

进入页面、刷新和真实空间的写操作都请求 API；失败后保留可操作的独立演示空间。演示有持续可见标识，数据仅保存在演示状态中，绝不补发到服务端。恢复连接后，真实账户按服务端响应同步，演示与真实空间分别保存。

真实消息先将稳定 `clientMsgId`、原 body／准入、草稿和 Outbox 写入 IndexedDB 严格持久事务，完成后才发送；网络未知保留原意图，先只读查原结果，不生成新 ID 或自动重发。缓存按服务器 origin、deploymentId、用户、personal、restoreEpoch 和服务器 deviceId 隔离。上游 AT／RT 留在 BFF，浏览器仅持有 HttpOnly／Secure Cookie；CSRF、密码和OTP本人凭据仅在内存，浏览器不保存密码、OTP或刷新凭据。需要恢复的状态动作保留独立原请求／原准入；它们不混入普通消息视图、导出或认证凭据。

服务端恢复数据改变 `restoreEpoch` 后，旧消息队列被冻结；旧缓存单独归档，历史重新拉取，不把旧操作变成新消息。页面关闭会提示尚存草稿／Outbox。浏览器存储能力和配额仍受系统限制，不能据此宣称达到强保护等级。

API 普通超时默认5秒，可在构建／开发时用 `VITE_API_TIMEOUT_MS` 配置为500～30000毫秒；启动探测3秒，附件请求120秒。当前服务端附件上限64 MiB，图片另受服务端20 MiB限制。Logo、图标、字体随包提供；自托管头像和图片异步加载，未就绪或失败保留本地Logo。每个动态列表提供完整空态及重新加载入口。

未读按新消息ID去重，编辑／反应不重复计数。有 `sync_self_state` 时只提交聚焦前台、无模态且通过真实命中检测的可见气泡ID，绑定原成员代际；不把打开会话或滚到底当全部已读。本人连续读点与稀疏观察由服务端合并，精确未读来自实时GET，失败显示 `~N` 本机估算；手动未读是独立标记。尚无S2的原S1仍使用本机阅读显示规则。通知默认不展示正文，个人静音停止相应本机通知，浏览器不支持通知也不阻断入库；不宣称外部推送或对方公开已读。

群成员移除／退出固定使用原看到的membershipGeneration；退出后该会话旧待发队列在严格事务中冻结，重新入群不自动恢复。群改名结果未知先刷新权威状态；转让及新治理动作使用原nonce／所见版本／actor与target代际，只查原结果，明确重试不换原body，真实转让不走ownerId PATCH。举报先保存原操作ID与理由，再提交；刷新或丢响应后沿原ID核对，不额外持久化被举报消息的原文预览。

头像先持久化原文件、操作ID、资料版本与恢复代次，再上传；未知结果沿原操作核对。历史头像操作返回 `current=false` 时仍重新读取当前资料，不能用旧结果回滚头像。管理员登录和治理写操作使用验证器MFA，功能修改保留同一请求与授权对账。恢复后的 `contentUnavailable` 消息显示占位，不开放正文或附件动作。

## 四、视觉、依赖与验证 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

页面采用安静的绿色会话工作区，桌面分栏，窄屏进入单个会话；保留键盘焦点、对话框焦点约束、输入法确认键、减少动效偏好与图片尺寸。素材来源与许可见[资源出处](./Public/资源出处.md)。

浏览器和真实 HTTPS 联调脚本位于[独立测试目录](../../../测试/前端/Web/README.md)。构建通过不等于完整需求验收；未启用的第三方能力及强保护能力按服务端能力开关处理。

源码的类型检查、协议反例、认证／同步／本人状态／独立草稿恢复／正式导出浏览器回归与独立生产构建见[前序回归报告](../../../项目相关报告/测试/回归/20261116-全项目回归/Web-CLI.md)。本人主动改密已接下节独立入口及[新源码证据](../../../项目相关报告/实现进度/20261116-剩余能力闭环/Web改密.md)；注入HTTP与真实HTTPS分别记录，登录／恢复表单不替代主动改密。

联系人详情按本人关系只读响应显示删除好友、拉黑／解黑和明确重开入站申请；不从对方资料推断私人策略。申请／重开先严格保存原ID，刷新后沿原ID核对；删除／拉黑前冻结此会话旧队列，不因重新加友重放。新消息保存原 `sendAdmission`，重试先实时核对实例能力且不替换原资格；旧资格被拒绝后持久冻结，无快照旧意图仅可对支持此合同的服务查原结果。

搜索与本人收藏使用服务端签名游标分页，明确提供加载更多、完整空态和重新加载；收藏不再借空搜索查询。打开结果前分别重新鉴权会话与原消息，支持前100会话之外的合法来源，撤回结果只显示当前占位。

结构化提及由用户明确勾选成员，名单与原消息事务一起持久化；普通@文字不产生提及。已显示的未读提及每轮最多20条轮转重验当前权威投影，block后不依赖新消息事件清旧提醒，编辑不会重复加数。群公告引用本群来源的contentVersion，个人收藏／反应／置顶不使公告失效；内容变更／失权／到期后不展示旧预览。公告原操作先严格落盘，未知结果先查原操作，已成结果不重复发布，旧结果也不回滚当前公告。

普通转发先重新核源contentVersion，变化后由用户重新选择；原proof、目标sendAdmission、ID及epoch严格事务入队，不复制正文／附件ID／回复／提及。已提交丢响应先纯查确认；未到达时只由明确重试在404后沿同ID／body再投。已缓存转发按批精确GET重新投影，源失效／依赖未知清正文与URL，离线不回退旧投影。媒体只使用当前转发消息的固定同源附件路径。[限定证据](../../../测试/前端/Web/forward.cjs/README.md)区分真实API和测试静态文件供给。

## 五、<span id="web-authoritative-sync">快照与连续增量</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

服务端明确启用 `authoritative_sync` 后，客户端先严格保存物理存储实例 UUID 和原登记请求，绑定本人、部署、personal、恢复代际及服务器 device。完整快照逐页验证原始 reference／body envelope 的 SHA-256、对象版本及完整清单，再验证最终权限，取得首次连续增量后才原子安装正文投影与游标。页缺失、摘要错误、存储异常、迟到身份、权限变化或新恢复代际均不能提交半份快照。网络未知保持原快照请求，明确过期或失效后另取新切面，旧暂存保留。

初次校验期间显示重新加载入口，暂停正式消息发送。原 Outbox 与草稿保留；旧页面保存只能合并草稿，不能回滚新投影。未知或缺项不当作删除，先把原合法普通正文留在不供云视图展示的隔离持有者；明确 global 同事务清理当前／隔离／旧设备视图的正文和媒体侧信。global 是终态，不能被晚到的原文或更高版本“复活”。转发投影正文不进普通持久缓存，展示前重新精确鉴权，未验证项可逐条重新加载。

同步消息只有本人／原 ID 还不足以销队列：必须携原完整 body 向只读 `message-results` 查得 200，并在提交事务中再次核对本人、会话路由及仍未改变的原意图，才能移除对应队列；查无结果、冲突或未知不转成创建消息 POST。清空消息库后不能凭旧 Cookie 继承原存储登记，须重新证明身份。已有登记／暂存／游标责任时，服务端关闭同步能力也不会绕回旧历史轮询。

完整业务消息DTO中的global同样立即生效，先核原消息／会话路由、原写入client ID及本人归属，再清持久持有者和当前引用预览；不等待下一轮同步。迟到forward和私有附件不能越过新事实代际，媒体完成前重读共享ledger。IDB写失败时先清当前RAM并限制云视图，原事实保留在本轮内存待重试，不冒充持久成功；崩溃／断电故障边界另验。辅助原请求查单503／超时只产生零proof，保留原队列，不阻挡已验证global提交。

没有同步责任、且服务端未启用本能力的已有开发环境继续使用原历史接口；这不等于完整同步验收。S1 coverage 不包含本人状态；实际启用S2后按下一节处理。附件字节、qualified ACK、after_receipt、正式导出及普通迁移仍待各自完整合同，不以同步游标代替收讫。协议／存储／投影测试与真实 HTTPS 的范围分别见[测试入口](../../../测试/前端/Web/README.md)。

## 六、<span id="web-self-state">本人状态与文本云草稿</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

服务端实际支持 `sync_self_state` 时自动选择schema2，旧控制、原envelope和stage归档，同一物理UUID登记新stream；本地数据库版本不变，原消息Outbox不重写。本人metadata与游标同严格事务提交，owner revision与对象version分开；偏好、会话视图、本人read／observation和draft分别保存，不把精确实时计数混入快照cut。

| 入口 | 行为与默认值 | 持久化／边界 |
| --- | --- | --- |
| 侧栏筛选 | 默认收件箱不列归档／隐藏；全部、归档、隐藏可找回；原pinnedRank排序 | 归档／隐藏不删除消息或授回云权限，筛选为本页状态 |
| 会话详情“我的同步状态” | 置顶、一天静音、归档、隐藏、手动未读；无记录为服务端v0默认 | PATCH核用户所见version；手动未读另核自身generation，正常阅读不清标记 |
| 设置字号 | 小／标准／大；本机默认标准，S2使用本人的当前服务端偏好 | 语言与主题仍为本机设置，不宣称已跨端同步 |
| 云草稿 | 明确保存当前独立文本及可选回复引用；单份不超过16KiB，不上传附件队列 | 先核所见云version，变化先刷新；回复精确GET核原contentVersion与dr1，不持久quote正文 |
| 采纳／清空／复制 | 云草稿不自动覆盖本机输入；采纳非空独立文本同时退出旧编辑／回复并清@；清云草稿仍保留当前本机输入 | namespace、文本、编辑／回复／提及快照CAS；不自动发送或修改原Outbox |
| 原操作恢复 | 完整原body／method／nonce先落私有意图，结果未知先纯查；明确重试仍保原proof、CAS和epoch | `prepared`待确认，`retired`停止原发布并允许精确GET恢复独立文字；旧成功`current=false`不回滚现值 |
| 设置→独立草稿恢复 | 从本人私有draft metadata的非当前／只读会话和本库pending／prepared／retired原draft操作发现候选；默认仅标识，不预览旧正文 | 点选精确GET后只显示当前获准ownedText及GET.recovery；不伪造Conversation、不授回云历史，不把原操作ownedText当当前值 |

元数据位于独立 `sync-personal|namespace`，原动作在 `self-state-operations|namespace`；普通Space、消息导出与认证库不携带这些恢复资格。原操作跨正常同步guard轮换可继续核原事实，切换family／设备／epoch不能补绑；能力撤回停止写，不降级借旧协议。前台观察使用真实气泡hit-test且排除模态，读点按原成员期核验；当前Web仍为transport-only，不向后端声明native断电耐久资格。

具体代码：[协议](./Src/SelfStateProtocol.ts)、[原操作服务](./Src/SelfStateActions.ts)、[面板](./Src/SelfStatePanel.tsx)、[事务](./Src/SyncStore.ts)、[主流程](./Src/App.tsx)。验证范围与原始失败见[当前本人状态报告](../../../项目相关报告/测试/前端/Web/20261116-S2本人状态/README.md)，不把代码存在或局部通过写成全部I完成。

恢复入口由[SelfDraftRecovery](./Src/SelfDraftRecovery.tsx)实现。复制前重取并比对所见版本／独立文字／恢复operation；清空要明确确认，再将所见version交原服务CAS。本页只核对原单时固定`resume(false)`，404／未知不顺手PUT／DELETE或替换旧proof。没有自动采纳、切到另一个会话或发送动作；本机其它输入及正式Outbox不变。family／namespace切换、页面销毁与迟到请求都有原上下文及mount代际检查，排队动作不借新账号继续。

原channel仍pending／prepared且结果未知时，既有服务会阻止新的清空操作；保留原意图并提供只读核对／重载，不擅自退休或重投旧写。十语、白天／黑夜／跟随系统沿用当前主题；完整空态、重载及选择态可见。私有metadata／原操作继续用既有IndexedDB键，不新增库／迁移；当前GET只在组件RAM，不把来源引用或quote复制进恢复展示。

本轮[10组独立恢复浏览器证据与私有生产构建](../../../项目相关报告/测试/前端/Web/20261116-独立草稿恢复/README.md)使用真实Chrome／React／IndexedDB／Web Locks，HTTP函数及剪贴板接收端为显式注入，全部`/api`网络阻断；未连接E2或其它后端。新包`index-D_uZ6muW.js`不追认旧D5包11真实HTTPS／26本地结果；实际服务加载切换及离群文字真接口待owner独立窗口。

## 七、<span id="web-personal-export">正式本人导出入口</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

设置页新增本人导出面板。新建前核当前实例与恢复代际及 `chat_export`，完整 `{requestId,restoreEpoch}` 原请求和摘要先写入严格 IndexedDB 事务；创建结果未知只查 `data-export-results`，仅用户明确重试且查无原结果时沿同一原 body 提交。任务记录只含原请求／摘要、时间、任务ID和独立取消原单，不保存聊天正文、制品字节、下载票或密钥。列表明确是此浏览器记录，清站点数据不会代替服务端取消。

任务状态逐次取当前本人结果，刷新未知立即收起旧下载入口；新建与下载在能力撤回后停止，已有任务仍能核对或按原取消请求收尾。family／namespace／epoch、挂载代际、请求次序、严格事务和实际Web Locks共同限制迟到结果及排队动作，不借新账户继续。未连接的演示空间仅提示连接／重载，不生成私人数据的假ZIP。

任务时间优先使用所选语言的浏览器Intl格式；浏览器没有该语言数据时使用本地时区的`YYYY-MM-DD HH:mm`，不自动显示宿主语言。日期回退的失败反例与修复后19组组件验证见[当前回归](../../../项目相关报告/测试/回归/20261116-全项目回归/Web-CLI.md)。

下载每次重取当前ready状态及RAM短票，经统一BFF `apiFile` 携family与下载票header取得Blob；上游AT／RT仍不进入JS，票不进URL、DOM或持久库。只接受ZIP MIME、安全服务端文件名和有界完整ZIP目录，截断、超限或未知不触发下载。对象URL在交付后及组件销毁时回收；“交给浏览器”不宣称已落设备磁盘。已保存ZIP无法由后续服务器取消远程删除。

本轮代码与边界见[独立入口](../../../测试/前端/Web/data-export.cjs/README.md)及[中央报告](../../../项目相关报告/测试/前端/Web/20261116-正式本人导出/README.md)。资源恢复后，锁定TypeScript7检查、18组实际Chrome注入及独立生产包`index-D15iqubR.js`构建通过，三张实际截图已检查；HTTP与保存端为显式注入，不证明真实HTTPS／用户磁盘落盘。未将后端2b58或旧S2／恢复包证据外推为本包完整交付。

## 八、<span id="web-password-change">本人主动改密与原请求恢复</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

设置页“修改本人密码”使用[后端2.3协议](../../后端/Go/接口契约/README.md#own-password-change)。新建需当前已登录本人、原family／device／恢复代际及实时`own_password_change`；输入当前密码、新密码及再次确认，管理员提供验证器OTP，并明确确认全部设备需重新登录。可以显示／隐藏密码；提交、换原请求、换family或组件销毁时清空表单。新密码按NFC的15～128码点／最多512字节校验，不trim显著空格，不以恢复码代替本人当前密码。

| 入口 | 默认／持久化 | 生命周期与未知结果 |
| --- | --- | --- |
| 修改密码 | 默认不发起；原nonce／用户名／本人／family／device／epoch／namespace与状态先严格IDB提交 | 新建先匿名查原结果，明确未见才以原family＋CSRF首写；不自动refresh，不把后来登录的凭据用于旧原单 |
| 本浏览器原请求／重新加载 | 使用既有JobsIM v1／spaces的独立`password-changes\|origin\|deployment`键；输入本人用户名查本地非秘密记录 | 不持久密码对、OTP、原密码请求body或无钥摘要；不自动联网查单、重投或换nonce；清站点数据会丢失本机恢复入口 |
| 只核对原结果 | 本人重新输入原规范化密码对；固定原nonce／用户／device／epoch | 专用transport始终`credentials:omit`，无family／CSRF／OTP；未知404只保原责任，不创建改密 |
| 明确重试原请求 | 重新输入原证明并确认；先纯查原单 | 已prepared可匿名续原责任；未见原单只允许原family／本人／设备仍相同且cap可用的明确授权。另一个当前family不得发布旧原意图 |
| 结果与重新登录 | `pending`／`changed`／`retired`／未知分列，所有代际保留字符串 | unknown原责任阻止该family普通API及冷BFF自动学习；成功仅停止原family并退休原namespace，转新登录，不自动代登录。历史结果不清后继Cookie／身份／namespace |

十语与三主题沿用现有设置和语义色；原请求列表有完整空态、重载和更多入口。纯结果查询和历史续尾无Cookie，即使收到Set-Cookie也不影响后来登录；首次有凭据的改密与现有登录／刷新共用生命周期及刷新WebLocks。原AT／RT仍只在BFF服务端。

本地真实浏览器反例、表单截图、精确输入和构建边界见[闭环报告](../../../项目相关报告/实现进度/20261116-剩余能力闭环/Web改密.md)；未把注入服务或私有构建当作已更新实际运行服务、真实TOTP／journal或用户账户验收。

## 九、<span id="web-account-deletion">本人注销与无普通会话的数据权利入口</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

设置页可申请注销；登录／注册／恢复弹窗也可打开“注销本人账号”，无普通会话仍能核对、查询和在服务端冷静期内取消既有申请。新建必须当前本人原family／device／恢复代际、当前密码及明确确认，管理员另需OTP。接受或结果未知后停用原family，成功取消仍需重新登录，不恢复旧会话。演示空间不模拟私人注销成功。

| 入口 | 默认／持久化 | 生命周期与未知结果 |
| --- | --- | --- |
| 申请注销 | 默认不提交；严格IDB保存原nonce、本人／用户名、family、device、epoch、namespace及尝试状态 | 先匿名只查原结果；新建才携原family与CSRF，不自动refresh。明确404不自动创建；原family之外不能首次授权旧请求 |
| 本浏览器记录／重新加载 | `account-deletions\|origin\|deployment`，复用现有JobsIM v1／spaces；仅非秘密元数据 | 原申请、注销ID／所见版本、服务端截止和原取消nonce分列；密码／恢复码／OTP／proof／原证明body及无钥hash不落盘 |
| 只核对原申请／明确重试 | 重新输入当时原密码，原请求／device／epoch固定 | 只查匿名`deletion-results`，404零写；已prepared可匿名续原责任，首次未见仍只允许原family。额外依赖403保unknown，不能据状态码解除冷family门禁 |
| 验明本人并查询 | 当前密码或一枚恢复码，管理员密码需新OTP；也可登记已有注销ID与所见版本 | 匿名获取query-only RAM证明，再查当前原单。恢复码会消费；query证明可据服务端当前版本恢复取消未知，界面不自动重基取消写 |
| 取消注销 | 明确确认，原取消nonce先持久化，使用当前精确版本的cancel-only证明 | 结果未知先核对；无既成取消且服务端仍requested时，用户可沿原nonce明确再试，不换新取消ID。取消后仍需新登录 |

历史查询与续尾始终`credentials:omit`，无普通family／CSRF，不让迟到响应清后继Cookie。新建共用生命周期／refresh WebLocks；普通API和冷BFF context学习会检查持久注销责任。表单提交、切换记录／凭据类型／family及销毁时清空凭据；十语、白天／黑夜／跟随系统继承当前设置，列表有完整空态、重载和更多入口。

完成注销后，当前密码／MFA／恢复码已删除，不能再据注销ID与旧密码新签证明。已有原创建完整上下文与原密码可继续只查该原单；之前签出的query证明在其短期有效期内仍可观察终态。跨浏览器仅持注销ID／旧密码不能冒充已完成后的本人恢复资格。代码与23组真实浏览器、改密22／导出19／认证16／App8回归和独立构建见[实现报告](../../../项目相关报告/实现进度/20261116-剩余能力闭环/Web注销.md)；真实HTTPS与真实账号注销另验。

## 十、<span id="web-group-governance">群治理、邀请与入群原责任</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

群详情增加全员禁言、普通成员慢速、容量、目标成员禁言／解除、管理员任免、原资格转让和解散；只在服务端所见role和state允许时开放。`canRecover`仅在当前admin有独立operator grant且群owner_unavailable时显示恢复表单，OTP与step-up只RAM，不能靠普通账号恢复自动取得群主。成员、邀请、申请都支持更多页；审批主显当前公开姓名／账号，时间与申请态次级，已抹除者占位。

| 入口 | 默认／持久化 | 原请求与生命周期 |
| --- | --- | --- |
| 群设置／成员动作 | 默认取服务端快照；全员禁言关、慢速0、容量200来自服务端，用户不提交则不写 | 在用户确认前固定群version、actor MG／RG；选目标时复制其原MG／RG。确认后不默默重取或替换资格；角色ABA、退重入和版本改变拒旧 |
| 创建／撤销邀请及审批 | 原nonce和非秘密body先严格IDB提交；期限、次数、审批项显式 | 管理动作同样带原群与actor代际。撤销／审批按governance/operations原actor＋nonce只查，不把他人列表结果当自己的原事实 |
| 本浏览器原群操作 | 既有JobsIM v1／spaces内`group-operations\|origin\|deployment\|userId`，原family／device／epoch／namespace继续固定 | 原组404零POST；用户明确重试只沿原body。重新登录可核对旧actor事实，但不同family／device／epoch不能首次发布旧原单；失效原单不自动重基 |
