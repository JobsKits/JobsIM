## <span id="jobs-toc-heading-2" data-jobs-toc="v2">入口、持久化与生命周期</span><!-- jobs-toc:heading-end -->

会话详情新增“我的同步状态”：置顶、一天静音、归档、隐藏、独立手动未读、云草稿保存／清空／复制／采纳与原请求核对；侧栏提供收件箱／全部／归档／隐藏筛选，设置字号在 S2 下使用服务端 CAS。静音影响本机通知，独立未读标记不被普通阅读操作清除。

协议使用服务端实际能力自动选择 S2。旧 S1 控制、origin、原 envelope、stage 保留归档，同一物理 store UUID 重新登记新 stream，原消息 Outbox 不变。S2 本人投影与游标在同一个 IndexedDB strict 事务提交，owner clock 和对象版本分开，计数维持字符串；同 origin／position 冲突和错误本人／实例导致整笔回滚。

本人元数据放在 `sync-personal|namespace`，本人原操作放在 `self-state-operations|namespace`，不进入普通 `Space`／消息导出。操作先保存完整原 body、摘要、nonce、epoch、CAS、成员代际、da1／dr1，再按完整原 body 查单；未知不自动换 ID 或补新 proof。新逻辑动作与原意图重试分开，能力撤回停止写操作。读取和草稿的服务端 operation UUID 不假定等于客户端 requestId。已完成原操作再次核验当前性，`current=false` 不恢复旧值；普通同步轮次 guard 变化后可查原事实，不篡改原请求。新动作先纯查同通道旧责任，未确认不创建另一意图；明确409且完整原单再查为精确404时才记本地 rejected并保留原body，不能把普通网络失败当拒绝。

草稿由本人文本和纯回复 ID／contentVersion 引用组成。新回复选择核精确消息版本及 dr1，旧意图不会刷新资格。`prepared` 保持待确认；`retired` 停止原发布，恢复文本仅通过明确 GET 展示。云草稿读取、保存、清空均不自动替换本机输入；保存／清空核用户所见版本，已变化先刷新再操作。明确采纳在原 namespace／文本、回复、编辑模式及结构化提及快照 CAS 下提交，同时清旧编辑和 @，不生成消息 Outbox；空云草稿不提供清空本机输入的采纳动作。dr1 不写普通持久消息视图。

活跃会话不再一律清未读，只提交前台、已聚焦且无阻挡模态的真实消息 ID；气泡须位于视口及 thread 内并通过五点 hit-test，覆盖面板也不计入。排队前捕原成员代际，GET 不得借新代际发布旧观察；稀疏观察不能跨过未见空洞，未知 creation 顺序不造连续读点。精确未读来自实时 GET，失败显示本机 `~N` 估算，手动未读独立显示。账号／family／epoch／设备变化检查贯穿排队、请求及本地提交。
