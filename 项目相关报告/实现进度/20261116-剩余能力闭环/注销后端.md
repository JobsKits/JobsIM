## <span id="jobs-toc-heading-2" data-jobs-toc="v2">一、源码与行为 <a href="#前言">🔼</a> <a href="#🔚">🔽</a></span><!-- jobs-toc:heading-end -->

- [申请与公共原单](../../../代码/后端/Go/account_deletion.go)要求当前本人密码、原设备／epoch／nonce；已存在原单可匿名同体续跑，结果入口始终只查。所有注销公开响应均不写 Set-Cookie，避免迟到 HTTP 头清后来登录的浏览器 Cookie。
- [受限证明](../../../代码/后端/Go/account_deletion_proof.go)提供5分钟 query／cancel 用途证明，密码／单次恢复码／当前管理员MFA审计核验各走独立路径；proof不能被当作普通会话。query可重新验证已见旧版本后绑定当前版本，以找回未知取消；cancel必须精确所见原版本，不能静默重基，未来版本拒绝。
- [Identity责任](../../../代码/后端/Go/account_deletion_identity.go)先持久围栏与最小 journal intent，再排空导出／转发并撤销全部 family／RT／BFF。取消仅清该原注销引用，保留封禁／墓碑／恢复态／其他撤权，旧会话不复活；取消结果未受保护时继续禁止新登录。
- [Governance仲裁与worker](../../../代码/后端/Go/account_deletion_governance.go)默认7天，可配置0～30天；同一行锁／版本CAS在取消与processing之间只授一方资格。DB当前时刻到期后才能进入不可逆清理，owner未逐一确认不显示completed。初始unknown、cancel_pending及processing均沿原责任续跑。
- [各owner清理](../../../代码/后端/Go/account_deletion_owner.go)按有界页复用消息global生命周期／源与派生排空，按精确owner和原UUID删除附件／未提交对象／头像字节并fsync；清资料、私人偏好、联系人、本人sync流／快照／read／view／草稿，退出成员，失效群主转只读owner_unavailable；保用户名占用键和最小法定／安全事实。
- [恢复安全](../../../代码/后端/Go/account_deletion_safety.go)重放注销请求／处理／完成、单次恢复码消费与owner擦除；取消只有result可以降该门禁。隔离恢复开放前再删除已journal保护的精确恢复媒体文件，并清旧群治理授权。shared hooks仅接现有migrate／handler／journal／replay／worker，不改第三方源码。

接口DTO、错误与默认值见[契约2.4](../../../代码/后端/Go/接口契约/README.md#own-account-deletion)。完成后密码／MFA／恢复码已清，不能用旧密码跨浏览器新签受限proof；原创建完整上下文仍可查该原单，或在原5分钟内用既有query proof观察completed。仅有deletionId不能冒认本人。
