## 🔥 <span id="前言">前言</span>

本片依据[需求生命周期合同](../../../需求/IM需求明细表.md/IM需求明细表.md#receipt-deletion)实现 [**Go**](https://go.dev/) 后端的发送时冻结、累计确认、保留任务与删除事实恢复。默认 `cloud_history` 没有隐式正文到期清理。原生客户端必须先取得精确构建／物理库验证批准；SQL夹具不形成合格端证据。

## 一、<span id="source">源码行为</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

| 入口／生产文件 | 当前行为 |
| --- | --- |
| [receipt_delivery.go](../../../代码/后端/Go/receipt_delivery.go)、[receipt_delivery_worker.go](../../../代码/后端/Go/receipt_delivery_worker.go) | 发送时固定人类成员代际、有效会话的已批准设备、物理store与qualification；空设备用户保持未达。正文与完整对象独立累计；必须满足每人规则，旧CV／epoch／代际／manifest ACK不补新内容。设备撤销、退重入、物理库与批准变化来自权威事实；第一齐备时间与待发布完成事实在同一PG事务内保存。 |
| [retention_policy.go](../../../代码/后端/Go/retention_policy.go)、[retention_edit.go](../../../代码/后端/Go/retention_edit.go) | GET／PUT会话retention，稳定requestId、预期策略版本；默认变化只影响新发送。正文n显式0～604800；附件独立模式／n／硬期限。after_receipt完成或排期后拒编辑；此前编辑换CV与确认代际，复制原目标且不延原FrozenAt／硬边界。 |
| [retention_worker.go](../../../代码/后端/Go/retention_worker.go)、[retention_clock.go](../../../代码/后端/Go/retention_clock.go) | 期限先独立journal确认；PG租约与token栅栏；before → journal intent → 排空引用／草稿／导出持有者 → 正文、范围墓碑、after与任务结果同事务 → journal result → complete。源更新必须仍持原pending operation；过期worker不能提交或宣告完成。数据库UTC用于截止，运行中用单调耗时检查跳变；已检测时钟异常持久闭锁。 |
| [retention_read.go](../../../代码/后端/Go/retention_read.go)、[retention_access.go](../../../代码/后端/Go/retention_access.go) | worker停机不延长已知硬期限。云正文、转发、导出、附件入口按当前授权／截止拒读。cloud_only不发本地焚毁命令；原件续取只允许原frozen target、原当前物理库、已提交描述ACK与原成员代际。global随后递增范围墓碑并同步；乱序cloud任务不能降级。 |
| [retention_safety.go](../../../代码/后端/Go/retention_safety.go)、[retention_legacy.go](../../../代码/后端/Go/retention_legacy.go) | 恢复按原绝对截止重放，缺源备份保留逻辑ID删除floor。初次迁移只登记activation之前的旧message＋attachment绑定；旧件只保原读取合同，明确legacy=true／cleanupEligible=false，不补造目标、期限或自动删除。新缺assignment与任何保护floor不借legacy旁路。 |
| [retention_readiness.go](../../../代码/后端/Go/retention_readiness.go) | afterReceiptEnabled由当前物理库精确批准、真实JetStream发布／消费连接、管理能力、同epoch message与journal耐久就绪共同派生；单个ACK结果继续明确不代表范围齐备。 |

`QueueRetentionErasure(ctx,messageId,operationId,scope,dueAt)` 是注销／治理复用入口：调用者先鉴权并持源EX栅栏，scope仅cloud_only／global，operationId稳定；兼容旧无assignment消息，但generation=1仅作为显式任务身份，不虚造收讫事实。各任务原因与绝对截止独立，未来global不提前参与当前清理范围。

实际覆盖：空目标／全撤销不能冒充送达、显式独立n=0、首次完成不重置、journal故障留pending、原发送目标累计／错误CV、编辑不扩目标及旧ACK失效、过期租约拒提交、导出持有者同步撤交付、cloud→未来global不提前烧／后续global不降级、原绝对deadline恢复、缺源floor、成员／物理库／批准拒旧、检测时钟异常持久闭锁。

边界：精确原生构建和端侧事务资格仍须独立验证；本机时钟检查不能证明跨站可信时间或未被检测的停机期间全机时钟前跳；跨故障域强保护、外部业务Webhook订阅与死信交付未由本片声称完成。媒体物理清理及旧件独立global事实见[媒体收讫清理](./媒体收讫清理.md)。首次全量曾有读游标23505与旧媒体夹具误把503错误JSON当原件流两项失败；前者修生产并发仲裁，后者换真实迁移／原tuple夹具并增加Content-Type断言，原失败见[保留日志](./收讫清理证据/首次全外置真实PG-两项失败.jsonl)。没有修改／启停用户旧实例或第三方源码，没有提交／推送。
