## 🔥 <span id="前言">前言</span>

本片对应[正式备份恢复合同](../../../需求/IM需求明细表.md/IM需求明细表.md#disaster-recovery-requirements)。新增候选实现用于原生八物理域库的CMS冷备，不能用循环单库Restore代替协调恢复。当前限定主路径已真实通过：八物理域库、最新current ledger交接与新epoch、原MacOS部署脚本的严格HTTPS启动／登录／历史／原件下载及精确停止。17.60秒首个成功轮保留；最终对159份已复制输入复跑15.90秒，跑后逐字节一致。未清理缓存、数据、SDK或模拟器。

## 一、<span id="implementation">候选源码</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

| 文件／入口 | 实现内容 |
| --- | --- |
| [deployment_restore_spec.go](../../../代码/后端/Go/deployment_restore_spec.go)、[deployment_disk.go](../../../代码/后端/Go/deployment_disk.go) | 私有spec严格解码，文件路径相对spec解析；来源实际连接必须回环，目标端口／目录隔离、保持4GiB余量；先CMS认证解密再遍历tar白名单，拒路径穿越／链接／重复／超限；macOS AppleDouble仅丢弃有界regular元数据，不恢复扩展属性。 |
| [deployment_restore.go](../../../代码/后端/Go/deployment_restore.go)、[deployment_restore_finalize.go](../../../代码/后端/Go/deployment_restore_finalize.go) | 一次协调八域；目标自有双PG及各域用户／口令／物理收据；源全部离线且八域身份匹配；逐域原子导入及owned checkpoint；归档journal只在抛弃数据库中读原锚，不参与信任恢复；逐owner重放最新事实、撤旧family／证明／导出与草稿，按受保护事实清旧媒体，并校当前仍需保留原件的长度／SHA。 |
| [deployment_handoff.go](../../../代码/后端/Go/deployment_handoff.go) | 锁内最新current ledger仅分配一次epoch，handoff绑定原operation／spec摘要／目标物理journal身份；再导出此刻最新ledger至目标。原source ledger保留，普通journal启动与state／append因目标物理身份不符拒绝，避免两边并行开闸。中断仅原单可续，已完成原结果查单不重新执行。 |
| [jobsimops](../../../代码/后端/Go/cmd/jobsimops/main.go) | `--mode deployment-restore-plan --deployment-spec <私有JSON>`；实际写入另要求 `--mode deployment-restore --offline`。结果不含DSN、口令、Token或私钥。 |
| MacOS／Linux原部署脚本 | 读非可执行`restore-layout.conf`选回目标端口，显式进程环境仍优先；`restore.pending`存在时run早拒。新token与broker目录重建，旧broker／admission资料隔离，保持CA、部署ID、合法媒体和源数据。两份实现仅默认动作不同。 |

spec v1字段：`version:1, operationId, backup, backupSha256, recoveryKeyFile, sourceState, targetState, repository, postgresBin, openssl, sourceDatabaseUrls:{identity,directory,conversation,message,media,control,sync,journal}, targetDatabaseUrls?:{同八域}, mainPort,journalPort,httpsPort,internalBasePort,natsPort,publicHost`。来源需能执行受控恢复的本机operator权限；目标必须是与源不同的空state。运行秘密只存工程外私有文件；恢复钥不复制到目标／备份目录。governance继续与identity共物理库，不能漏其schema。

## 二、<span id="evidence">已验与待验</span> <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

| 层次 | 真实结果 |
| --- | --- |
| 初版生产包 | 最终冻结输入随真实专项完成生产／外置编译与原部署入口原生构建。159份后端／部署／测试输入跑前复制，跑后全部不变；Web构建输入亦随该冻结保存。 |
| MacOS／Linux布局函数 | 在Mac宿主分别执行zsh／Bash的实际`load_restore_layout`函数，目标五端口／host读取正确；两平台脚本各自两份语法通过。不是Linux原生PG启停证据。 |
| 首次真实恢复专项 | 用本人独立双PG随机八域、实际NATS和生产处理器完成源注册／关系／消息、原件固定输入、冷态CMS，以及备份点之后的实际撤回／主动改密；plan被macOS自动`._owner`等元数据拦下，未导入目标、更未声称目标运行。此轮保留失败，后续固定namespace后完成真实主路径。[原JSONL](./恢复迁移证据/首次恢复专项-AppleDouble与浏览器夹具失败.jsonl)／[命令](./恢复迁移证据/实际专项命令.zsh.txt) |
| 资源 | 最终source／target共16个已知自有监听端口全无监听；源八域、加密包、私有恢复钥和目标保留工程外。用户a4原实例与root的Canonical联调实例未被本片控制。[最终停止证明](./恢复迁移证据/最终资源停止.json)；历史低盘暂停[原门禁](./恢复迁移证据/资源门禁.json)保留。 |
| 完整验收 | 实际已过：八域原子导入、最新ledger一次epoch2交接、原source普通journal拒启动、目标原脚本严格HTTPS、新登录／旧JWT与旧未发epoch拒绝、备份后撤回不复活、替换密码均拒并进入恢复状态、原件正常下载、新broker及原stop收尾。最终3项（含继任handoff纯合同与群申请页真实PG）全过，包16.862秒；恢复主方法15.90秒。[最终JSONL](./恢复迁移证据/最终冻结-八域与原入口真实通过.jsonl)、[冻结一致性](./恢复迁移证据/最终恢复冻结一致性.json)、[结构化结果](./恢复迁移证据/最终真实结果.json)、[产物SHA](./恢复迁移证据/最终规范入口产物SHA256.txt)、[停止证明](./恢复迁移证据/最终资源停止.json)。仍待：故障逐点终止／中断原单重启、真实第二跳canonical→后继恢复、再次原入口重启与Linux／Windows原生环境。用例位于[独立专项](../../../测试/后端/接口/deployment_restore_pg_test.go)，未跑过部分保留待核。 |

Windows当前原入口使用预置外部PG，owner／broker清单与MacOS／Linux自管双PG格式不同，本候选尚未交付Windows原生恢复适配或实测。不会把平台名字、归档目录验真、部分SQL重放或本次单条主路径等同所有灾备场景通过；普通端侧迁移另开独立协议，不复用本整库恢复。
