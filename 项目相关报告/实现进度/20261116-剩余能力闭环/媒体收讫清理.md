## <span id="jobs-toc-heading-1" data-jobs-toc="v2">一、当前实现</span><!-- jobs-toc:heading-end -->

本轮在[正文与冻结目标链路](./收讫清理.md)之外，实际补齐媒体 owner 的读取授权、独立附件保留、对象完成后清理和旧备份拒复活。没有把正文描述 ACK 当成完整原件收讫，也没有把未登记的新对象按旧合同放行。

| 源码 | 已实现行为 |
| --- | --- |
| [media.go](../../../代码/后端/Go/media.go)、[media_receipts.go](../../../代码/后端/Go/media_receipts.go) | 当前本人授权后，向 message owner 复核 user/device/store/epoch、源对象和当前内容版本。cloud_only 后只有原冻结且已提交正文描述 ACK 的当前合格物理设备可续传；当前成员／历史资格仍优先。完整描述按原文件大小与 SHA256 校验，不使用预览。 |
| [media_retention.go](../../../代码/后端/Go/media_retention.go) | 固定绝对对象截止和完整对象收讫延迟独立；`nil` 与显式 `0` 分开。原 FrozenAt、独立硬截止与已保护的较早截止不因编辑／恢复延长。持久 floor 先经 journal 保护；worker 持同机全局 EX，排空公开下载、转发和归档读取，再取消精确归档持有者、unlink 原 UUID regular file、fsync、记结果。失败保原字节与原责任。 |
| [media_export.go](../../../代码/后端/Go/media_export.go)、[forward_media.go](../../../代码/后端/Go/forward_media.go) | 转发／导出不绕过独立对象截止；读取使用共享围栏。公开普通原件与转发的每次 Read 都检查截止，跨硬期限停止后续字节。归档登记不扩大源期限，清理前须收到治理 owner 对精确 job 的取消回执。 |
| [media_legacy_erasure.go](../../../代码/后端/Go/media_legacy_erasure.go) | 旧附件只认可 owner 登记的 `legacy=true,cleanupEligible=false`，保留原读取合同，不造目标、manifest、延迟或自动期限。旧件后来完成 global 时，只接受原已确认 global job/event 的独立 erasure-only 计划；以独立最小 journal 事实和任务恢复物理清理。 |
| [media_retention.go](../../../代码/后端/Go/media_retention.go)／main／journal／restore 钩子 | 独立媒体 clock alarm 持久闭锁不可逆清理；UTC 与运行中单调耗时复核，重启不清已检测异常。typed intent/result 的截止统一为 PostgreSQL 微秒精度，重放不改原操作身份。旧快照恢复的原字节仍需沿原删除责任重新清理。 |

`media.retention_floors` 保存非秘密原绑定、版本、manifest 摘要、较早绝对截止和 terminal/bytes/result 阶段；`media.legacy_erasure_tasks` 仅保存已成 global 的原 job/event/epoch/截止；`media.lifecycle_clock` 保存时钟闭锁。文件字节不写入安全日志。worker 扫描限定已绑定聊天对象，`retention_checked_at` 使失败／旧对象不会永久饿死后面的对象；不扫描任意目录或修改兄弟文件。

## <span id="jobs-toc-heading-2" data-jobs-toc="v2">二、验证记录</span><!-- jobs-toc:heading-end -->

[12 个外置方法](../../../测试/后端/接口/media_retention_pg_test.go)为 2 纯规则＋10 真实随机 PG；[测试说明](../../../测试/后端/接口/media_retention/README.md)列明门禁和反例。复用了生产迁移、SQL、handler、真实文件和本地文件锁，身份／原 source plan／治理 RPC 为明确进程内夹具，不能冒充真实 HTTPS 或原生存储审批。

已运行的完整外置真实 PG 候选由协作后端代理封存于[全外置原始日志](./收讫清理证据/全外置真实PG.jsonl)：该候选 135 顶层 pass／9 skip／0 fail，包含当时媒体 11 方法、正文保留 12 方法及既有真实原件描述／下载排空反例。其后 erasure-only 桥与第12媒体方法完成，[最终联合专项](./收讫清理证据/最终联合专项真实PG.jsonl)36顶层方法／44含子项pass事件、0fail／skip；其中`TestMediaRetention`12方法全部通过，不把44事件写成44顶层。对应[21份最终输入](./媒体收讫清理/20261117-011515-最终输入/索引.json)与媒体子集结果均已封存。

[最终离线候选](./媒体收讫清理/20261117-005654-最终离线构建/结果.json)的后端统一外置、`go vet ./...`、`go build ./...` 全过；该轮数据库门禁主动移除，PG 方法明确跳过。erasure-only 增量后生产包编译通过。命令均使用锁定 Go 1.27.4、`GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off GOMAXPROCS=2 GOFLAGS=-p=1`。

精确执行方式：

```shell
python3 测试/后端/运行测试.py --backend-only --go /选择的Go可执行文件
go test -json -overlay /本轮私有overlay.json ./... \
  -run '^Test(MediaRetention|Retention|ObjectReceiptPGMediaChecksRealOriginalFile|ObjectReceiptPGOriginalDownloadDrainsBeforeSourceWrite)' -count=1
go vet ./...
go build ./...
```

最初 PG 夹具把同一参数同时推断为 UUID/text，修为明确转换；重放反例最初没有向独立 journal 写 typed intent，已补真实原意图并统一数据库微秒表达，保留原结果拒绝断言。[19 pass／1 fail 的原始前轮](./媒体收讫清理/20261117-005503-联合PG-前轮原始.jsonl)继续保留。旧慢下载夹具原先到达错误 JSON，修成真实迁移和授权后，阻塞前先确认原件 Content-Type，原 EX 等待与最终完整字节断言保留；没有通过删除反例获得全过。

本轮每秒检查可用空间，低于 4 GiB 或超时只停止自己的进程组；已记录最低余量约 9.8 GiB。没有清理旧证据、真实用户数据或第三方文件，没有提交／推送。

## <span id="jobs-toc-heading-3" data-jobs-toc="v2">三、实际边界</span><!-- jobs-toc:heading-end -->

| 状态 | 范围 |
| --- | --- |
| 源码已实现 | 新发送冻结对象的当前授权、独立期限、收讫后清理；明确旧白名单的读取与已成 global 的独立物理清理；精确归档取消、重启／journal 重放拒复活、时钟闭锁。 |
| 实际已验 | 上述已封存候选的 PG／文件／锁反例，完整离线与构建；真实 owner 的目标资格和旧白名单由正文专项验证分列。 |
| 待核 | 真实 HTTPS 多角色原件收讫到物理清理、真实批准原生构建／物理库、跨集群完整加密备份恢复，以及 WindowsOS／Linux 原生文件系统行为。本机 clock guard 不证明停机期间独立可信时间。 |

当前对象仍执行一对象一原 message 的绑定合同；普通转发复用来源授权，归档是派生持有者，均不直接创建另一聊天绑定。本片没有实现任意多 message 共同持有同一对象的引用计数 API。未提交上传／头像的账号域抹除需注销 owner 独立交接，不能以本聊天 worker 宣称所有账号字节均已删除。

恢复审查增量：发现原备份强制读取所有media metadata对应文件，会将已合法unlink的原件当损坏。新增[media_restore.go](../../../代码/后端/Go/media_restore.go)的`MediaObjectNeedsBackup`，仅已保护terminal／legacy erasure／账号floor可省字节；普通缺文件及未知metadata不放行。`ClearRestoredRetainedMedia`在离线目标复制并完成owner safety replay后，仅清精确UUID regular对象，不把deadline-only事实当成删除；已恢复的旧字节仍需原结果续尾。[最终追加索引](./媒体收讫清理/20261117-013901-备份钩子最终/索引.json)封存当前7份生产媒体源与2份测试，13个媒体方法（2纯／11真实PG）全pass。联合日志另有独立`FreshBrowserPassword`夹具403失败交主流程处理，没有把整份联合说成全过。完整八域恢复部署证据仍由多库恢复主流程补齐。
